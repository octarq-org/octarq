The model gateway connects the workspace to a model backend. AI features use the gateway. They do not keep their own keys.

A workspace with no provider has no AI. The platform does not use instance credentials for a workspace.

## Add a provider

**Settings › Model Gateway**, then **Add provider**, opens the provider form.

1. Enter a name. The name is a label for operators.
2. Select a backend.
3. Enter the API key.
4. Optional: enter a base URL for a proxy or a local model.
5. Optional: select a default model and a cheap model.
6. Select **Save**.

The form reads the model list from the provider. Do not type a model name. A claude key with no base URL reads Anthropic's own list.

The first provider becomes the default provider.

A local backend, such as Ollama, needs no API key.

## Test a provider

Select **Test** beside a provider. The gateway sends one small request to the backend.

- **OK**: The key, the base URL, and the model work together.
- **Error**: The message from the backend shows the cause.

## Choose the default provider

The default provider serves every AI request of the workspace.

Select **Make default** beside a provider. A workspace has one default at a time.

Delete a provider only after you make another one the default. A workspace with no default refuses AI requests.

## Set model prices

**Model prices** sets the cost of one model per one million tokens.

Select **Add price**. Enter the model identifier that the backend uses, then enter the input price, the output price, and the reasoning price. Select **Save**.

AI features that charge a budget refuse a model without a price. Add the price before you use the model.

A price of zero marks a model with no token cost.

## Use a coding agent

A coding agent can spend the workspace provider.

Codex, Cline, aider, and opencode use the OpenAI API format. The workspace serves that format at `/v1`.

The agent needs three settings:

1. Base URL: your workspace address, then `/v1`.
2. API key: a workspace token. An admin mints the token.
3. Model: the agent reads the list. Do not type a model name.

The agent asks `GET /v1/models` and shows the models that the provider serves. It then sends each turn to `POST /v1/chat/completions`.

The gateway forwards a chat completion to the provider unchanged. Tools, streaming, and structured output keep working.

## Use Codex

Codex uses the OpenAI Responses format. The workspace serves that format at `/v1/responses`.

Codex 0.167 no longer loads the chat format. It needs this route.

Edit `~/.codex/config.toml`:

```toml
model = "<a model from the list>"
model_provider = "octarq"

[model_providers.octarq]
name = "octarq"
base_url = "<workspace address>/v1"
env_key = "OCTARQ_TOKEN"
wire_api = "responses"
```

Set `OCTARQ_TOKEN` to a workspace token before you start Codex.

The gateway converts each turn to the provider format and converts the answer back. Tools and streaming keep working.

## Use Claude Code

Claude Code uses the Anthropic Messages format. The workspace serves that format at `/v1/messages`.

Set three environment variables:

1. `ANTHROPIC_BASE_URL`: your workspace address.
2. `ANTHROPIC_AUTH_TOKEN`: a workspace token.
3. `ANTHROPIC_MODEL`: a model that the provider serves. Read the list on the Model page.

Claude Code sends tools and streaming to the same routes. The gateway converts them to the provider format, and converts the answers back.

The requested model reaches the provider unchanged. Set `ANTHROPIC_MODEL` to a model the provider serves. A wrong name returns the provider error.

The Model page has a button named **Read the model list**. It shows the names that the provider serves. A native Anthropic key also works on this button.

:::note
The provider key stays in the workspace. The agent never holds it.
:::

## Use opencode

opencode finds the workspace itself. It reads `/.well-known/opencode`, runs the command that document names, then loads the provider block. The block lists every model the provider serves. You do not type a model name.

1. Mint a workspace token on the tokens page.
2. Run `opencode auth login <workspace address>`.
3. Enter the token when opencode asks for it.

Set `OCTARQ_TOKEN` before step 2 to skip the question. The command reads the variable and stores it as the credential.

Add a model in the console, then run `opencode reload`. The new model appears in the picker.

`curl <workspace address>/.well-known/opencode` shows the same document opencode reads.

## Access permissions

The model gateway page needs the workspace admin role.

Members cannot read or change provider credentials.
