Store and manage third-party integrations, environment variables, SSH keys, database passwords, and 2FA codes in **Settings › Integrations**.

## Workspace vault

The page shows one workspace vault. There is no personal vault and no scope selector.

- **Workspace**: Shared integrations, environment secrets, and service tokens for your organization.
- Workspace members can inspect metadata, test connections, view version history, and read live TOTP codes.
- Workspace admins can create, edit, reveal, roll back, set defaults, import `.env` files, and manage service tokens.
- Workspace owners can export secrets and delete items.

## Add a credential

1. Open **Settings › Integrations**.
2. Select a collection and an environment (`default`, `prod`, `staging`, `dev`).
3. Click **New item**.
4. Choose a category and a template, for example OpenAI, Stripe, S3, Key-Value Secret, or 2FA TOTP.
5. Enter the item name, the optional key name, and the required fields.
6. Click **Create**.

## Reveal, test, and rotate secrets

- Secret values stay hidden in list views. Each item shows a `vault://` reference that you can copy.
- Click **Reveal** on an item to view or copy its current value. Every reveal creates an audit entry.
- Click **Test** on supported integrations, databases, SSH keys, or TLS certificates. The test checks the credentials without showing secrets.
- Edit an item to save a new version. Open **Versions** to inspect history. Click **Rollback** to restore an earlier version.

## Import and export `.env`

1. Select a collection and an environment.
2. Click **Import** and paste `KEY=VALUE` lines or JSON. This creates or updates secrets in bulk.
3. Workspace owners can click **Export** to download `.env` or JSON output for that collection.

## Service tokens

Create a scoped read-only service token under the **Service Tokens** tab. CI pipelines and external apps then pull secrets from `/api/vault/raw` for one collection, environment, and folder prefix. The token needs no user session.

```bash
curl -H "Authorization: Bearer octvq_..." "https://your-octarq-host/api/vault/raw?format=env"
```

:::tip
Service tokens only read workspace items that match their exact collection, environment, and folder prefix. They never access instance secrets.
:::

## Instance Vault

Instance administrators can open **Instance Settings** (`/instance/settings`) and scroll to **Instance Vault**. This section manages system-wide credentials, for example OAuth client secrets (`instance.oauth.google`, `instance.oauth.github`) and metrics tokens (`instance.metrics_token`).
