Octarq 在底层基于严格的多租户架构构建。所有托管域名、邮箱、短链接、API 令牌、出站 Webhook 及审计日志均归属于具体的 **组织 (Organization / Workspace)**。工作区构建了严密的数据与管理隔离边界，支持跨国团队、企事业单位及多项目业务在同一套 Octarq 实例中独立安全运行。

## 工作区数据隔离边界

- **物理逻辑双重隔离**：在某个工作区内创建的所有业务数据，仅对该组织下的授权成员可见。切换工作区后，控制台看板与 API 查询将自动收敛至当前选中组织。
- **租户专属子域名**：工作区可拥有专属的自动化子域名，同时受平台基准域名防抢注机制保护。
- **杜绝跨租户渗透**：后台异步任务、Webhook 推送及 MCP 工具调用均在租户专有投影中运行，绝不泄露其他工作区的数据。

## 角色权限矩阵表

Octarq 定义了三层标准的组织工作区角色：

| 业务操作 / 功能模块 | Member（成员） | Admin（管理员） | Owner（所有者） |
|---|---|---|---|
| 查看短链、统计报表、邮箱及 DNS 解析记录 | ✅ | ✅ | ✅ |
| 创建与编辑短链、邮箱及 DNS 解析记录 | ✅ | ✅ | ✅ |
| 导出分析数据与 CSV 报表 | ✅ | ✅ | ✅ |
| 配置出站 SMTP 发件服务及黑名单名单 | ❌ | ✅ | ✅ |
| 维护出站 Webhook 与告警通知渠道 | ❌ | ✅ | ✅ |
| 绑定并维护 DNS 服务商账户（Cloudflare、DNSPod） | ❌ | ✅ | ✅ |
| 邀请团队成员并分配 Member 角色 | ❌ | ✅ | ✅ |
| 晋升或降级 Admin 管理员角色 | ❌ | ❌ | ✅ |
| 维护账单支付、订阅套餐及品牌外观定制 | ❌ | ❌ | ✅ |
| 转让工作区所有权或注销解散工作区 | ❌ | ❌ | ✅ |

## 切换与新建工作区

### 切换当前活跃工作区

1. 点击左侧边栏顶部的工作区切换器（Workspace Switcher）。
2. 在下拉菜单中选择任意个人工作区或团队组织。
3. 控制台将立即无缝刷新并呈现目标工作区的数据视图。

### 创建新的组织工作区

1. 打开左侧边栏顶部的工作区切换下拉菜单。
2. 点击 **+ 创建工作区**。
3. 输入组织名称（例如 `Acme Global`）。
4. 点击 **创建并切换**。您将自动成为该新建工作区的首位 **Owner（所有者）**。

## 邀请团队成员（24 小时令牌有效期）

1. 进入 **设置 → 工作区 → 成员**（或按 `⌘K` / `Ctrl+K` 搜索“成员”）。
2. 点击 **邀请成员**。
3. 填入被邀请人的邮箱地址并指定其初始角色（**Member**、**Admin** 或 **Owner**）。
4. 点击 **发送邀请**。
5. **加密令牌生命周期**：系统会生成带密码学签名的专属邀请链接并通过邮件下发（`https://your-octarq-host.com/invite/{token}`），该链接在 **24 小时** 内有效。若超时未接受，管理员可点击 **重新发送** 刷新生成新令牌。

## 末位 Owner 防降级与防删除保护

为避免工作区陷入无人掌管的死锁状态：

- **强制单一所有者锁定**：每个工作区必须至少拥有一位处于激活状态的 **Owner**。
- 若工作区仅剩一位 Owner，任何试图将其降级为 Admin/Member 或从组织中移除的操作，均会被系统底层拦截并返回 HTTP 400 Bad Request（*“cannot remove or demote the last owner”*）。
- **所有权平滑转让**：若需退出管理，现有 Owner 必须先邀请或将另一位成员提拔为 `Owner`。在存在多名 Owner 后，原 Owner 方可安全降级或退出组织。

## 成员移除时的级联清理

当管理员从工作区中移除某位成员时：
- 该成员将即刻失去对该工作区所有页面与资源的访问权限。
- 该成员在该工作区内签发的所有 [API 令牌](/help/api-tokens) 将触发级联物理删除，防止自动化残留凭证产生越权风险。
