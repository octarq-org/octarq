Octarq provides a hardened authentication framework engineered to protect developer workspaces and user identities. It supports standard email/password authentication, TOTP two-factor authentication (2FA), single-use recovery codes, self-service password recovery, social OAuth (Google and GitHub), and registration policies.

## Email and Password Authentication

- **Password Hashing**: User passwords are encrypted using modern cryptographic hashing (Argon2id/bcrypt) with unique per-user salts. Plaintext passwords are never logged or stored.
- **Session Security**: Authenticated browser sessions are managed via secure, `HttpOnly`, `SameSite=Lax` cookie tokens with cryptographic session invalidation on logout.

## Two-Factor Authentication (TOTP 2FA)

Add a critical layer of account defense using time-based one-time passwords:

1. Go to **Settings → Account → Security**.
2. Under **Two-Factor Authentication (TOTP)**, click **Enable 2FA**.
3. Scan the displayed QR code with your authenticator application (such as 1Password, Google Authenticator, or Apple Keychain).
4. Enter the 6-digit verification code generated by your app and click **Confirm & Enable**.
5. **Store Recovery Codes**: Octarq displays 10 single-use emergency recovery codes. Store them in an offline password manager or physical vault.

:::caution Recovery Codes Requirement
If you lose access to your primary 2FA authenticator device, recovery codes are the **only** self-service method to regain access to your account. Each recovery code can be used exactly once.
:::

## Self-Service Password Reset and Session Invalidation

If a user forgets their account password:

1. Click **Forgot password?** on the sign-in screen.
2. Enter the registered account email and submit.
3. Octarq sends an email containing a cryptographically signed reset token valid for **1 hour**.
4. The user clicks the link and establishes a new password.
5. **Universal Session Revocation**: When a password is reset, Octarq automatically invalidates all active session tokens across all browsers and devices immediately.

## OAuth Provider Configuration (Instance Admins)

Enable one-click social authentication for team members:

1. Go to **Settings → Instance → Authentication**.
2. Expand the **Google** or **GitHub** configuration section.
3. Supply the credentials generated in the respective developer console:
   - **Client ID**: Your OAuth application public client ID.
   - **Client Secret**: The associated confidential client secret (encrypted at rest using AES-GCM).
4. Configure the exact callback redirect URI in your provider console:
   - Google: `https://your-octarq-host.com/auth/callback/google`
   - GitHub: `https://your-octarq-host.com/auth/callback/github`
5. Click **Save**. The OAuth sign-in buttons appear immediately on the login portal.
6. **Auto-Verification**: Accounts created or authenticated via verified OAuth providers are marked as email-verified automatically.

## Registration and Sign-In Policies

Instance administrators can configure tenant onboarding rules under **Settings → Instance → Authentication**:

- **Allow Public Sign-Up**: Toggle off to disable open registration and enforce an invite-only deployment where users can only join via administrator invitations.
- **Require Email Verification**: Toggle on to block unverified email accounts from logging in until they complete an email verification link.

:::caution This is a Pro feature
For centralized enterprise identity management, Octarq Pro includes Enterprise Single Sign-On (SSO) supporting OpenID Connect (OIDC) and SAML 2.0 protocols with Okta, Azure Active Directory / Entra ID, Keycloak, and Google Workspace, complete with Just-In-Time (JIT) provisioning.
:::
