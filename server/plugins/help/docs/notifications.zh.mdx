Octarq 提供统一的业务告警与通知推送引擎。当工作区内发生关键事件（例如收到事务邮件、SMTP 发信失败、DNS 解析状态异常漂移、短链点击达标等）时，系统可实时将告警信息广播至指定的外部通讯渠道。

## 支持的告警通知渠道

### 1. Telegram 机器人通知

Telegram 具备跨端极速推送能力且免收任何通讯费用：

1. 在 Telegram 中搜索并打开 [@BotFather](https://t.me/BotFather)，发送 `/newbot` 指令创建专用通知机器人，并复制生成的 **Bot Token**（例如 `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ`）。
2. 将该机器人拉入目标 Telegram 群组或频道中，或直接向机器人发起一次对话。
3. 获取目标接收方的 **Chat ID**（群组通常为带前缀的负整数，如 `-100123456789`）。
4. 在 Octarq 中前往 **设置 → 工作区 → 告警**（或按 `⌘K` / `Ctrl+K` 搜索“告警”）。
5. 点击 **添加渠道**，选择 **Telegram Bot**，填入 **Bot Token** 与 **Chat ID** 后点击 **保存**。

### 2. 自定义 HTTP Webhook 告警

面向自建 SIEM 系统、Discord 机器人、钉钉、企业微信、飞书或内部监控平台：

1. 前往 **设置 → 工作区 → 告警**。
2. 点击 **添加渠道**，选择 **自定义 Webhook (HTTP POST)**。
3. 填入接收端点的公网可达 URL（例如 `https://alerts.internal.example.com/api/octarq`）。
4. 点击 **保存**。系统将以结构化 JSON 载荷推送事件级别、触发时间戳、所属工作区及详细摘要。

## 测试通知即时验证

配置任意告警渠道后，建议立即发起端到端测试：

1. 在 **告警** 设置列表中找到刚刚创建的渠道行。
2. 点击右侧的 **测试发送** 按钮。
3. Octarq 将即时组装一条模拟的合成告警报文并发起网络推送。
4. 页面将实时反馈返回的 HTTP 状态码、往返网络耗时以及服务商具体的报错信息（若推送失败）。

## 安全防护与高可用保障

### 内网与私有地址防护

为保障系统网络安全，告警 Webhook 会自动对目标地址进行安全校验。任何尝试访问局域网、私有网络或云平台内部地址的请求均会被自动拦截，全面保护企业内部资产。

### 异步非阻塞分发

所有告警通知均在后台异步处理。外部即时通讯服务的网络延迟或临时中断不会影响核心邮件接收、短链跳转或控制台的正常操作。每次推送均设有 10 秒超时防护。

:::caution 本功能为 Pro 专属功能
Octarq Pro 商业版进一步提供了原生 Slack 告警频道集成，支持 Slack Block Kit 富文本卡片展示、会话路由以及严格的域名固定防护（`hooks.slack.com`）。
:::
