Octarq 的出站 Webhook 引擎会在工作区内发生关键事件时，实时向外部服务器发送 HTTP `POST` 通知，用于打通自动化流程、数据同步和自定义告警。

## 能力概览

- **实时事件投递**：`email.receive`、`email.send_failed`、滥用举报等系统事件即时回调。
- **精细的事件订阅**：可订阅指定事件主题，也可用通配符 `*` 接收工作区全部事件。
- **HMAC-SHA256 载荷签名**：每个请求都带 `X-Octarq-Signature` 头，内含用你的密钥算出的 HMAC-SHA256 签名，接收端可据此校验来源、防止篡改。
- **自动生成或自定义密钥**：可以自带签名密钥，也可以让 Octarq 自动生成一个安全随机密钥。
- **SSRF 防护与超时控制**：投递请求有严格超时，外部服务器变慢不会拖累工作区自身的操作。

## 使用方法

### 1. 注册 Webhook 端点
1. 进入 **设置 → 工作区 → Webhook**（或按 `⌘K` / `Ctrl+K` 搜索「Webhook」）。
2. 点击**添加 Webhook 端点**。
3. 填写有辨识度的**端点名称**和目标 **Endpoint URL**（例如 `https://api.yourdomain.com/hooks/octarq`）。
4. （可选）填写自定义**签名密钥**（留空则自动生成）。
5. 选择**订阅事件**（可选 **全部事件 (\*)** 或勾选具体事件）。
6. 点击**添加 Webhook 端点**。

### 2. 校验 Webhook 签名
收到回调后，在接收端校验 `X-Octarq-Signature` 头：

```crypto
signature = HMAC-SHA256(raw_request_body, signing_secret)
```

Node.js / Express 示例：

```javascript
const crypto = require('crypto');

function verifyOctarqWebhook(req, res, next) {
  const signature = req.headers['x-octarq-signature'];
  const expected = crypto
    .createHmac('sha256', process.env.OCTARQ_WEBHOOK_SECRET)
    .update(req.rawBody)
    .digest('hex');

  if (signature === expected) {
    next();
  } else {
    res.status(401).send('Invalid signature');
  }
}
```

### 3. 删除端点
在 **设置 → 工作区 → Webhook** 中管理已注册的端点，可随时查看端点密钥或删除不再使用的端点。

:::tip
本地开发和调试时，可以用 `ngrok`、`hookdeck` 之类的工具先看清载荷长什么样，再把接收逻辑部署到生产。
:::

## 为什么重要

出站 Webhook 让 Octarq 与下游系统解耦：你可以触发客户自动化流程、把邮件通知灌进自建数据库、或者拉起服务器部署，全程不需要轮询 Octarq 的 API。
