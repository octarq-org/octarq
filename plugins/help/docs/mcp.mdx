Octarq provides a Model Context Protocol (MCP) server that lets AI desktop clients and remote agents query short links, emails, DNS records, and system data.

## Transports and Security

- **Local stdio Transport**: Runs `octarq mcp` as a local subprocess for desktop tools like Claude Desktop or Cursor. Tools are scoped to your workspace.
- **HTTP / SSE Transport**: Accepts remote connections at `/api/mcp/sse`. Authenticates callers using standard [API Tokens](/help/api-tokens) (`Authorization: Bearer oct_...`) and scopes all tool calls to the caller's active workspace.

Every tool is a read-only, workspace-scoped projection over your data — short links, mailboxes, emails, domains, and a full data export. There is no raw-SQL tool on any transport: an arbitrary query cannot be confined to a single workspace, so the capability is not offered rather than merely restricted.

## Local stdio Setup (Claude Desktop)

Add the Octarq binary to your `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "octarq": {
      "command": "/usr/local/bin/octarq",
      "args": ["mcp"],
      "env": {
        "OCTARQ_DB_DSN": "/path/to/octarq.db"
      }
    }
  }
}
```

## Remote SSE Setup

To connect remote AI tools or web clients:

1. Generate an [API Token](/help/api-tokens) in **Settings → Account → API Tokens**.
2. Configure your client to connect to:
   - **SSE Endpoint**: `https://your-octarq-domain.com/api/mcp/sse`
   - **HTTP Header**: `Authorization: Bearer oct_your_secret_api_token`

## Example Queries

Once connected, you can ask your AI client:

- "List unread emails received today."
- "Show click statistics for short links created this month."
- "Check for failing DNS verification records across my domains."
