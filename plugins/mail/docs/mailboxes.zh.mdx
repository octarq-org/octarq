接收事务性入站邮件、配置 Catch-All 邮箱路由、查看原始 EML 邮件，以及设置出站 SMTP 发件服务。

## 接入入站邮件 Webhook

1. 进入 **日常运营 → 消息 → 邮件**，切换至 **Settings** 标签页。
2. 在 **入站配置** 下复制当前工作区的 **入站 Webhook URL** (`/api/webhook/{orgSlug}/email/inbound/{token}`)。
3. 在 Cloudflare Email Routing Workers 等邮件服务中，配置脚本将收到的原始邮件 POST 至该 Webhook 地址。
4. 配置完成后，发送至自定义域名的邮件将直接呈现在 **Mail** 邮箱收件箱中。

## 通用原始 EML 入站 Webhook

除了 Cloudflare Email Routing 之外，Octarq 提供了通用 Provider 无关的原始 EML 入站 Webhook 端点 `/api/webhook/{orgSlug}/email/inbound/raw/{token}`。该端点支持直接 POST 标准 RFC822 原始 EML 报文或 `multipart/form-data` 格式。token 是最后一段路径而非 Header——放在 `X-Octarq-Token` 或 `Authorization` 里的 token 会被拒绝。

### 常用邮件服务商配置示例

#### Mailgun Routes 配置
1. 在 Mailgun 控制台中进入 **Receiving → Routes**。
2. 创建新 Rule 匹配目标收件人（如 `match_recipient(".*@yourdomain.com")`）。
3. 添加 Action: `forward("https://your-octarq-host/api/webhook/{orgSlug}/email/inbound/raw/{token}")`。
4. 在请求头配置中添加自定义 Header: `X-Octarq-Token: <your-inbound-token>`。

#### SendGrid Inbound Parse 配置
1. 在 SendGrid 控制台中进入 **Settings → Inbound Parse**。
2. 添加 Host 与 Webhook URL: `https://your-octarq-host/api/webhook/{orgSlug}/email/inbound/raw/{token}`。
3. 勾选 **POST the raw, full MIME message**（推送原始完整 MIME 消息）。
4. 在反向代理/边缘网关上配置将入站请求附加 Header: `X-Octarq-Token: <your-inbound-token>` 或 `Authorization: Bearer <your-inbound-token>`。

## Catch-All 路由与保留前缀

1. 进入 **日常运营 → 消息 → 邮件**，切换至 **Settings** 标签页。
2. 在 **入站配置** 中开启 **启用 Catch-All 路由**。
3. 在 **保留邮箱前缀** 中填写用逗号分隔的前缀（如 `admin, support, postmaster`），防止系统保留地址被 Catch-All 路由误拦截。

## 配置出站 SMTP 发件服务

1. 进入 **日常运营 → 消息 → 邮件**，切换至 **Settings** 标签页，找到 **SMTP 发件配置** 区域。
2. 点击 **添加 SMTP 发件服务**。
3. 填入 SMTP 服务器主机（如 `smtp.mailgun.org`）、端口（如 `587`）、用户名、密码及默认发件人邮箱。
4. 点击 **保存**。密码将在后端通过 AES-GCM 加密存储。

> [!NOTE]
> 系统事务邮件（如成员邀请函、密码重置邮件）会默认使用当前工作区中配置的第一条有效 SMTP 发件服务。
